## Source review

`prepare_reference(..., contig_aliases=character())` validates a uniquely named character vector, validates every destination against actual indexed FASTA names, forbids redirecting an existing canonical FASTA name, stores a sorted quoted `contig_aliases.tsv`, and includes that table in reference sizes/MD5 receipts (`R/preservation.R:32`–`:82`, `:85`–`:99`). Many aliases to one real target are allowed. Unknown targets, duplicate names, missing values and reserved missing-value alias labels are rejected.

Reopening a reference reloads its table (`:118`–`:138`), and existing reference verification covers its bytes along with other reference files (`:141`–`:158`). Only the native-call chromosome vector is mapped (`:102`–`:109`, `:312`); original source columns, table identity and file source artifact are preserved. Unknown aliases continue strict exact-name behavior; they are not guessed. The new mapping receipt is distinct from normalization/reference/projection/parser versions (`:345`, `:528`, `:576`). File editions preserve the actual map as checksummed `reference_contigs.tsv` (`:561`–`:570`). No C++ or native ABI change is part of this extension.

The test script is `review-production-reference/fixes/review-contig-integration.R`; output is `review-contig-integration.log`, `mapped-results.tsv` and `integration-proof.txt`. It sources the reviewed R implementation and uses `Rcpp::sourceCpp` in its own R temporary build against the unchanged C++ source. - Untouched original `CHR` forms `1`, `chr1`, `NC_000001.10`, `CM000663.1`, crossed with present `rs9` / missing ID: all eight map to canonical chromosome `1`, canonical `rs2`, `swap`, beta `-0.3`. The `rs9 -> rs8 -> {rs2,rs3}` graph does not choose an arbitrary destination; coordinates resolve the appropriate target.
- Complete `A,<DEL>,*` context makes all eight swapped EAFs `NA`. `chr1` complement also returns missing EAF; a different contig's truly biallelic swap returns `0.8`.
- `result$source` is identical to the original input data.frame. File editions preserve exact source-artifact bytes. Their `reference_contigs.tsv` MD5 equals both the reference table and the recorded edition checksum.
- The reusable verified handle returns identical results. Canonical-name shadowing (`1 -> 2`), an unknown target, duplicate alias names and a missing-value label all abort without publishing an index.
- A no-map newly prepared reference and the pre-existing frozen no-map reference preserve strict-name behavior. No alias file is added to a reference with an empty map.
- Source and target alias-bearing references work with an explicit identity-chain projection. Projection remains `mss-projection-2`, binds exactly to the source reference's checksums including the alias table, emits canonical target chromosome `1`, and preserves uncertain EAF as missing. No source/target assembly inference occurs.
- Changing the alias file makes both path-based use and an existing live handle fail verification; restoring the exact bytes permits a freshly reopened use again.

All assertions passed. The integration retained `mss-preservation-4`, reference format `mss-preservation-2`, projection `mss-projection-2`, and the `mss-contigs-1` mapping receipt. Existing parser/C++/ABI behavior is unchanged by source inspection.
