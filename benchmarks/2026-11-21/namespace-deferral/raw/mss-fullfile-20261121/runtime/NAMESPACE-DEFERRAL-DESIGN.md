# VariantAnnotation startup deferral

Builder decision within the user's authorized MSS acceleration work. Experiment in `/private/tmp/mss-lazy-variantannotation-20261121`, branch `feat/lazy-variantannotation-20261121`, baseline a6de747 (product code identical to measured bfa192c). The frozen benchmark branch/builds/failed matrix remain unchanged.

Goal: reduce ordinary tabular/preservation startup cost while preserving all VCF functions and scientific output. Keep VariantAnnotation in DESCRIPTION Imports; installation and ordinary Windows/R support must not change. Remove only eager VariantAnnotation NAMESPACE/roxygen imports; its existing `VariantAnnotation::` calls load it when needed. Make base data-frame/data.table binding explicit where the removed generic was inherited. Keep VCF's explicit `VariantAnnotation::rbind` and other heavy roots untouched. No lazy namespace hacks, hand-written global aliases, C++ modifications or changes to variant retention/orientation.

Alternatives: defer VariantAnnotation alone (chosen, narrow distinct ten-namespace static closure reduction); defer VariantAnnotation, BSgenome and rtracklayer together (potentially larger closure, broader S4/reference compatibility risk); retain eager imports and optimize only inner loops (leaves observed ~4s setup/~1GB tiny-process floor). Actual savings are not known. The user's goal of portable acceleration supplies the objective; this implementation choice is the builder's, not a claimed user selection.

Acceptance: fresh clean namespace call omits VariantAnnotation before/after ordinary preservation use; tiny hard/declaration golds both formats and multi-batch resident data.frame/data.table inputs match the frozen BFA outputs, classes/order and audit. Legacy mapping/BP data.table bind behavior, VCF read/convert/write/index and S4 split merges/ANN/metadata access work when VCF is first used and preservation works again after VCF load. Existing installed scoped tests and new targeted tests pass without skipping affected behavior. If a broader existing test needs absent real references, report it separately; never stub those packages or describe a focused suite as full qualification.

Measure BFA versus experimental candidate on identical normal installs/dependencies in balanced fresh-process pairs. Separate pure namespace load, setup, verified open, public call, whole worker wall and wait4RSS; measure first legacy VCF call and warm repeat separately.
